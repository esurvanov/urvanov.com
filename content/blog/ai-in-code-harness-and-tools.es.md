La diferencia entre Codex y Claude Code está en el modelo (GPT en Codex, Claude en Claude Code) y en el plan, porque en acceso al proyecto y en acciones son casi iguales. Conviene elegir el que use el modelo y la suscripción que tu equipo ya tiene. Cursor encaja si trabajas en un editor y quieres modelos de distintos proveedores; Hermes Agent, si necesitas cualquier modelo, también locales. Abajo hay un mapa, una tabla y una elección por tarea.

<b-chapter id="tasks" icon="venn" title="Qué harness para qué tarea">
  <b-why>La elección empieza por la tarea. Los dos círculos son familias de modelos, Claude y GPT: el lugar de un producto en el mapa muestra con qué modelos trabaja. Claude Code y Codex están ligados cada uno a su familia, Cursor y el chat están en la intersección, y Hermes Agent cubre por completo a Cursor y al chat, se solapa en parte con Claude Code y Codex y sale de ambos círculos, porque conecta cualquier modelo, también locales<b-proof href="https://hermes-agent.nousresearch.com/docs/integrations/providers" quote="Hermes Agent: local models via Ollama, llama.cpp, vLLM or LM Studio — “Ollama runs open-weight models locally with one command. Best for: quick local experimentation, privacy-sensitive work, offline use” — hermes-agent.nousresearch.com/docs/integrations/providers"/>.</b-why>

  <b-sublabel top="22">Preguntas habituales</b-sublabel>
  <b-qa>
    <q t="Claude Code o Codex">Coinciden en acceso al proyecto y en acciones, y difieren en el modelo (Claude y GPT) y en funciones concretas que cambian de versión en versión. La elección la marcan el modelo y el plan que el equipo ya tiene.</q>
    <q t="Cursor o Claude Code">Cursor trabaja dentro de un editor con un proyecto abierto y permite elegir entre modelos de distintos proveedores. Claude Code lleva una tarea de principio a fin en la terminal, pero solo con modelos de Claude.</q>
    <q t="Hermes Agent o Claude Code">Hermes Agent es un harness de código abierto: conecta cualquier modelo, también locales, y se paga por token. Claude Code está ligado a la familia Claude y a una suscripción. Elige Hermes para usar modelos de varios proveedores o un modelo propio.</q>
    <q t="Alternativas a Claude Code">De las que se tratan aquí: Codex (el mismo diseño, con modelos GPT), Cursor (un editor, modelos de varios proveedores) y Hermes Agent. <a href="https://opencode.ai" target="_blank" rel="noopener">OpenCode</a>, <a href="https://aider.chat" target="_blank" rel="noopener">Aider</a>, <a href="https://cline.bot" target="_blank" rel="noopener">Cline</a> y <a href="https://goose-docs.ai" target="_blank" rel="noopener">Goose</a> están construidos de forma parecida.</q>
  </b-qa>
  <b-finding>
    <ex>Una tarea impone dos requisitos al harness: si necesita el proyecto y qué familia de modelos encaja. Los agentes de proveedor trabajan con una familia, Cursor y el chat ofrecen elegir entre Claude y GPT, y los harness de código abierto aceptan cualquier modelo, también locales.</ex>
    <gen>Primero se elige el grupo según la tarea y luego el producto dentro del grupo. Claude Code y Codex difieren en el modelo y en funciones concretas del harness que cambian de versión en versión, pero en concepto están construidos igual. Por eso decide el modelo y el plan que el equipo ya tiene.</gen>
    <do>Describe la tarea en una línea y resuelve tres condiciones: si necesita el proyecto, si necesita a una persona en cada paso y si necesita un modelo de otro proveedor o un modelo local. Elige el grupo según esas condiciones.</do>
  </b-finding>

<b-chapter id="harness" icon="layers" title="Qué es un harness">
  <b-why>Un modelo responde con texto. El harness es todo lo que lo rodea: skills, herramientas, entorno y la persona en el circuito. Todo producto de IA tiene uno, desde un agente de terminal hasta un chat en el navegador<b-proof href="https://claude.com/blog/a-harness-for-every-task-dynamic-workflows-in-claude-code" quote="Anthropic calls Claude Code a harness: the post “A harness for every task” — claude.com/blog/a-harness-for-every-task-dynamic-workflows-in-claude-code"/>. Lo que cambia es la composición. La columna «Por API» usa Hermes Agent como ejemplo; hay muchos harness de código abierto, como OpenCode, Aider, Cline y Goose, y están construidos igual.</b-why>

  <b-qa>
    <q t="En qué se diferencia Claude Code de Claude en el chat">La familia de modelos es la misma; el harness es distinto. El chat responde en una conversación y no ve tu proyecto. Claude Code lee código, edita archivos y ejecuta comandos en el proyecto: en la terminal, en un editor, en la aplicación de escritorio o en un navegador. <a href="https://code.claude.com/docs/en/overview" target="_blank" rel="noopener">Documentación</a></q>
    <q t="En qué se diferencia Codex de ChatGPT">Vale la misma regla: los modelos GPT son los mismos, el entorno es distinto. ChatGPT mantiene una conversación sin acceso al proyecto; Codex trabaja con código y ejecuta comandos.</q>
  </b-qa>
  <b-finding>
    <ex>Los cuatro tipos difieren en dos propiedades: dónde se ejecuta el código y cómo funciona el acceso al modelo. El de código abierto y el Enterprise se ejecutan en tu ordenador y difieren solo en el acceso al modelo, de donde viene la diferencia de coste.</ex>
    <gen>Los tipos locales encajan con el trabajo con archivos y secretos de tu ordenador, la nube encaja con tareas largas y paralelas, el chat encaja con tareas sin acceso al proyecto. Las restricciones estrechan la elección: un plan Enterprise no está disponible en todas las jurisdicciones<b-proof href="https://www.anthropic.com/supported-countries" quote="Anthropic: “To the extent permitted by law, Anthropic reserves the right to not provide its products or services to entities whose majority direct or indirect ownership is attributable to nations other than those listed in our Supported Regions Policy” — anthropic.com/supported-countries"/>.</gen>
    <do>Decide si la tarea necesita archivos de tu ordenador, si el agente debe trabajar sin ti y qué modelo puedes usar. Lo primero apunta a un tipo local, lo segundo a la nube, y si no hay ninguna de las dos, al chat.</do>

  <b-sublabel top="22">Qué es qué</b-sublabel>
  <b-qa cols="3">
    <q t="Qué es Codex">El agente de OpenAI para trabajar con código: recibe una tarea, edita archivos y ejecuta comandos. Funciona en la terminal, en una extensión del editor y en la nube, con modelos GPT. El acceso al proyecto es lo que lo distingue del chat de ChatGPT. <a href="https://learn.chatgpt.com/docs/codex/cli" target="_blank" rel="noopener">Documentación</a></q>
    <q t="Qué es Cursor">Un editor de código con un agente integrado: el agente completa tareas por su cuenta, ejecuta comandos de terminal y edita código. Funciona en un proyecto abierto y admite modelos de varios proveedores. <a href="https://cursor.com/docs/agent/overview" target="_blank" rel="noopener">Documentación</a></q>
    <q t="Qué es Hermes Agent">Un agente de código abierto de Nous Research. Se ejecuta en tu ordenador, se conecta a distintos proveedores de modelos, incluidos Claude y modelos abiertos, y puede trabajar con un modelo local. <a href="https://hermes-agent.nousresearch.com/docs/user-guide/features/overview" target="_blank" rel="noopener">Documentación</a></q>

  <b-finding>
    <ex>Claude Code y Codex coinciden en acceso al proyecto y en acciones; difieren en el modelo y en funciones concretas del harness, y conceptualmente siguen siendo iguales.</ex>

    <q t="¿Codex o Claude Code: cuál elegir?">En acceso al proyecto y en acciones son casi iguales; difieren en el modelo, GPT en Codex y Claude en Claude Code. Elige el que use el modelo y la suscripción que tu equipo ya tiene.</q>

    <q t="¿Cuáles son las alternativas a Claude Code?">Codex, construido igual con modelos GPT, Cursor con su editor y Hermes Agent con cualquier modelo. OpenCode, Aider, Cline y Goose funcionan de forma parecida.</q>
