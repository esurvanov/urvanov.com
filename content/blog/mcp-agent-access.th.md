MCP เชื่อมเอเจนต์เข้ากับระบบงานจริง เอเจนต์จึงอ่านข้อเท็จจริงจากต้นทางแทนที่จะได้ฟังคำบอกเล่า ทำได้ง่ายและเร็ว: เข้าใจปัญหาที่มันแก้ แล้วมอบหมายการตั้งค่าให้เอเจนต์ทำเอง ด้านล่างอธิบายแนวคิด การเชื่อมต่อ สิ่งที่ได้รับ และสิทธิ์ที่ควรให้ ตัวอย่างงาน QA กับ MCP อยู่ในบทความ [QA กับเอเจนต์ผ่าน MCP](/blog/bug-report-to-reproduction-agent/#mcp)

<b-post series="harness">
<b-chapter id="what" icon="plug" title="MCP คืออะไร">
<b-why align="left">MCP คือปลั๊กมาตรฐานตัวเดียว เหมือน USB เชื่อมเอเจนต์กับ Jira หรือ GitLab แล้วมันดึงข้อมูลจากที่นั่นเอง <a href="https://modelcontextprotocol.io/docs/getting-started/intro" target="_blank" rel="noopener">อ่านเพิ่ม</a></b-why>
<b-why align="left">ภาพแสดงเส้นทางข้อมูลสองแบบ แบบแรก คนเล่างานให้เอเจนต์ฟัง และรายละเอียดหายระหว่างทาง แบบที่สอง เอเจนต์อ่านระบบเองผ่าน MCP และเห็นทุกอย่างที่คนเห็น MCP (Model Context Protocol) เป็นมาตรฐานเปิดที่เชื่อมแอปพลิเคชัน AI กับระบบภายนอก<b-proof href="https://modelcontextprotocol.io/docs/getting-started/intro" quote="MCP (Model Context Protocol) is an open-source standard for connecting AI applications to external systems."/> เอเจนต์มี MCP client ระบบมี MCP server และเซิร์ฟเวอร์บอกเอเจนต์ว่ามีข้อมูลและการกระทำอะไรให้ใช้</b-why>

<b-scene names="mcp-agent-access/retell-vs-mcp"/>
</b-lane>
<b-finding>
  <ex>ใน Jira เอเจนต์เห็นสิ่งที่คนเห็น: ตัวงาน PAY-142 ความเห็น และประวัติการเปลี่ยนแปลง ไม่ต้องหางานแล้วคัดลอกใส่บทสนทนา เมื่อขอ มันดึงงานที่เกี่ยวข้องมาได้ มันแสดงความเห็นในนามของคุณ สร้างงาน หรือเปลี่ยนสถานะได้ (หลังคุณยืนยัน) ครั้งแรกที่ใช้ควรรู้สึกว่า "ว้าว": นั่นแปลว่าตั้งค่าถูกแล้ว และมันง่ายมาก</ex>
  <gen>เอเจนต์มองกว้างกว่าคน: มันชั่งน้ำหนักงานข้างเคียง บทความในฐานความรู้ และการตัดสินใจในอดีต และเจอทางเลือกที่ไม่ชัดเจน ซึ่งงานเดียวไม่ได้แสดง ถ้าไม่มี MCP มันรู้เฉพาะสิ่งที่ถูกวางให้ คนเลิกเป็นพนักงานส่งของระหว่างหน้าต่าง และยังเป็นผู้ตรวจ</gen>
  <do k="ควรทำ">เริ่มจากระบบติดตามงาน: เริ่มง่ายและเร็วที่สุด วิธีเชื่อม Jira: <a href="#connect">ดูด้านล่าง</a> และนับว่าวันหนึ่งคุณคัดลอกข้อความใส่บทสนทนากี่ครั้ง: นั่นคือรายการระบบที่ควรเชื่อม</do>
</b-finding>
</b-chapter>
<b-chapter id="ours" icon="target-ring" title="บริบทของเอเจนต์และบริบทอื่น">
<b-why align="left">บริบทของเอเจนต์คือทุกสิ่งที่เอเจนต์เห็นพร้อมกัน (บทสนทนากับเอเจนต์ ไฟล์ของโปรเจกต์) บริบทอื่นคือทุกอย่างที่เหลือ (GitLab, Jira, บันทึกการประชุม, ฐานความรู้) สะพานระหว่างสองฝั่งคือ MCP: เอเจนต์มี MCP client และระบบมี MCP server</b-why>
<b-lane-art names="mcp-agent-access/contexts"/>
<b-why align="left">ด้านซ้ายของภาพคือบริบทของเอเจนต์: บทสนทนากับมันและไฟล์โปรเจกต์ที่มันเห็นพร้อมกัน ด้านขวาคือระบบอื่น: GitLab, Jira, tldv ที่มีบันทึกการประชุม, Confluence ที่มีฐานความรู้ จนกว่าจะเชื่อม MCP เอเจนต์มองไม่เห็นระบบเหล่านี้ สะพานระหว่างกันมีสองส่วน: MCP client ฝั่งเอเจนต์ และ MCP server ฝั่งระบบ</b-why>
<b-section-h3 top="18">บริบทคืออะไร</b-section-h3>
<b-why align="left"><a href="/materials/glossary/context/">บริบท</a>คือทุกสิ่งที่โมเดลเห็น ณ ขณะนั้น สิ่งที่ไม่อยู่ในบริบท เอเจนต์ไม่รู้</b-why>
<b-lane title="บริบท" color="accent" top="12">
<b-scene names="term:context"/>
</b-lane>
<b-why align="left">บริบทเปรียบได้กับโต๊ะที่มีทุกสิ่งที่โมเดลเห็นอยู่ตอนนี้: ข้อความในบทสนทนา ไฟล์ที่เปิดอยู่ ผลของการเรียกใช้ สิ่งที่ไม่ได้อยู่บนโต๊ะไม่มีอยู่สำหรับโมเดลจนกว่าจะถูกวางลงไป คำถามหลักเมื่อทำงานกับเอเจนต์จึงคือ บนโต๊ะของมันมีอะไร</b-why>

<b-why align="left">ตารางแสดงว่าเกิดอะไรกับข้อเท็จจริงตามที่มันอยู่ ข้อเท็จจริงในบริบทของเอเจนต์ (บทสนทนา ไฟล์โปรเจกต์): เอเจนต์ตอบจากข้อมูล ข้อเท็จจริงในระบบอื่น (GitLab, Jira, บันทึกการประชุม): เอเจนต์ดึงเอง แต่ต้องผ่าน MCP เท่านั้น ข้อเท็จจริงที่ไม่ได้เขียนไว้ที่ไหนเลย (ในหัวคน ในระบบปิด): เอเจนต์จะไม่เห็นและจะแทนที่ด้วยการเดา จึงได้กฎที่ใช้ได้จริง: เขียนการตัดสินใจไว้ในที่ที่เอเจนต์ดึงไปใช้ได้</b-why>

<b-section-h3 top="18">Hallucination: ส่วนที่ไม่มีหลักรองรับ</b-section-h3>
<b-why align="left"><a href="/materials/glossary/hallucination/">Hallucination</a>คือการเดาอย่างมั่นใจในที่ที่ไม่มีหลักรองรับ ดูลื่นไหลเท่ากับคำตอบจากข้อมูล รายละเอียดและคำแนะนำของ Anthropic อยู่<a href="#facts">ในส่วน hallucination ด้านล่าง</a></b-why>

<b-why align="left">เลือกระบบเหล่านี้เพราะเก็บข้อเท็จจริงสี่ชนิด: โค้ด งาน กฎ และการตัดสินใจจากการประชุม แต่ละแถวบอกว่าสูญเสียอะไรเมื่อไม่ได้เชื่อม Confluence มีข้อแม้: เชื่อมเฉพาะเมื่อหน้าเอกสารได้รับการดูแลดี (มีเจ้าของและวันที่ตรวจ) และให้เอเจนต์ตรวจภาพจริงเทียบกับโค้ดใน GitLab เชื่อถือได้ยิ่งกว่าถ้าเก็บข้อกำหนดและ spec ไว้ใน Git: ที่นั่นการแก้มีผู้แก้ วันที่ และเหตุผล</b-why>
<b-finding>
  <ex>คุณถามเรื่องบั๊ก แต่บทสนทนาไม่มีขั้นตอน เอเจนต์ค้นไฟล์โปรเจกต์ Jira ปิดอยู่สำหรับมัน มันจึงเขียนขั้นตอนเอง: มั่นใจ ลื่นไหล แต่แต่งขึ้น คุณเดินตามเส้นทางที่ไม่มีอยู่จริง</ex>
  <gen>เอเจนต์แทบไม่ตอบว่า "ไม่รู้" ถ้าคำตอบไม่อยู่ในบริบทของมันและบริบทอื่นปิดอยู่ มันจะเติมช่องว่างจากแพตเทิร์นทั่วไปและนำเสนอเป็นข้อเท็จจริง ทุกแหล่งที่เชื่อมไว้ลดพื้นที่ให้การแต่งเรื่อง</gen>
  <do k="ควรทำ">ทุกครั้งที่เอเจนต์ hallucinate ให้หาบริบทที่มีคำตอบ แล้วให้เอเจนต์เข้าถึงมัน เริ่มจากคำถามล่าสุดที่มันตอบด้วยเรื่องแต่ง</do>
</b-finding>
</b-chapter>
<b-chapter id="connect" icon="arrow-right" title="เชื่อม Jira อย่างไร">
<b-why align="left">เอเจนต์และ harness ของมันเชื่อมต่อได้เอง คู่มือ: <a href="https://support.atlassian.com/atlassian-rovo-mcp-server/docs/getting-started-with-the-atlassian-remote-mcp-server/" target="_blank" rel="noopener">Atlassian</a> และ <a href="https://code.claude.com/docs/en/mcp" target="_blank" rel="noopener">Claude Code</a></b-why>
<b-lane title="ทำเอง หรือมอบหมาย" color="accent">
<b-scene names="mcp-agent-access/one-phrase-setup"/>
</b-lane>
<b-why align="left">ภาพเปรียบเทียบสองวิธี ทำด้วยมือ: หาคู่มือ พิมพ์คำสั่ง ล็อกอิน และตรวจผล มอบหมายให้เอเจนต์: พูดประโยคเดียว เอเจนต์เชื่อม Jira เอง และสิ่งที่คุณทำมีเพียงล็อกอินผ่านเบราว์เซอร์</b-why>
<b-section-h3 top="14">บอกเอเจนต์</b-section-h3>
<b-copy-quote>เชื่อมเซิร์ฟเวอร์ MCP ของ Jira ตามคู่มือของ Atlassian และทดสอบกับงาน PAY-142: อ่านมันและสรุปความเห็น</b-copy-quote>
<b-why align="left">เอเจนต์รันคำสั่งเอง สิ่งที่คุณทำมีเพียงล็อกอินผ่านเบราว์เซอร์ (OAuth): เอเจนต์ไม่ได้รับรหัสผ่านของคุณ <a href="/blog/agent-hands-work-back-to-you/" target="_blank" rel="noopener">หากเอเจนต์ขอให้คุณทำเอง</a></b-why>
<b-section-h3 top="14">จะเกิดอะไรขึ้น</b-section-h3>
<b-steps-round>
  <step t="เอเจนต์เชื่อม Jira">ด้วยคำสั่งเดียว คุณไม่ต้องพิมพ์อะไร</step>
  <step hl t="หน้า Jira เปิดขึ้น — ขั้นสำคัญ">เสนอให้เอเจนต์เข้าถึง Jira คุณล็อกอินและอนุมัติ และเอเจนต์ไม่เคยเห็นรหัสผ่าน</step>
  <step t="เอเจนต์อ่าน PAY-142">เปิดงานพร้อมความเห็นและเล่าสรุป</step>
</b-steps-round>
<b-why align="left">ขั้นสำคัญคือขั้นที่สอง: คุณให้สิทธิ์เองด้วยการล็อกอินผ่านเบราว์เซอร์ เอเจนต์ไม่เห็นรหัสผ่านของคุณ และได้รับเฉพาะสิทธิ์ที่คุณยืนยันบนหน้า Jira ขั้นที่หนึ่งและสาม เอเจนต์ทำเอง</b-why>
<b-callout icon="shield-check"><b>อ่านอย่างเดียว</b> คุณอาจเลือกสิทธิ์อ่านอย่างเดียวในหน้านั้นไม่ได้เสมอไป ไม่เป็นไร: เอเจนต์มักอ่านและแทบไม่เขียนอะไรจนกว่าคุณจะสั่ง</b-callout>
<b-details-more summary="ทำด้วยมืออย่างไร" top="12">
<b-scene names="mcp-agent-access/setup-steps"/>
<b-copy-code>
  claude mcp add --transport http atlassian https://mcp.atlassian.com/v2/mcp
  /mcp               # log in via browser (OAuth)
  claude mcp list     # status: connected / needs login / failed
</b-copy-code>
<b-scene names="mcp-agent-access/scopes"/>
<p>การตั้งค่าอยู่ที่ไหนและใครเห็นเซิร์ฟเวอร์: <a href="/blog/mcp-scopes/">ขอบเขต MCP ใน Claude Code</a></p>
</b-details-more>
<b-why align="left">ด้วยมือคือสามคำสั่ง: เพิ่มเซิร์ฟเวอร์ ล็อกอินผ่านเบราว์เซอร์ด้วย /mcp และตรวจสถานะ สถานะมีสามแบบ: เชื่อมแล้ว ต้องล็อกอิน หรือผิดพลาด แผนภาพด้านบนแสดงทีละขั้น และขอบเขตด้านล่างบอกว่าการตั้งค่าเก็บที่ไหน</b-why>
<b-finding>
  <ex>เอเจนต์รันคำสั่งและตรวจการเชื่อมต่อเอง และงาน PAY-142 ถูกอ่านครบพร้อมความเห็น นั่นคือช่วงเวลา "ว้าว"</ex>
  <gen>การเชื่อมต่อใช้เวลาไม่กี่นาที ขอบเขต "Project" เก็บการตั้งค่าไว้ในรีโพซิทอรีเพื่อให้ทั้งทีมได้เซิร์ฟเวอร์ชุดเดียวกัน ทั้งสามขอบเขตอธิบายใน<a href="/blog/mcp-scopes/">ขอบเขต MCP ใน Claude Code</a></gen>
  <do k="ควรทำ">มอบหมายการตั้งค่าให้เอเจนต์ แล้วเทียบคำตอบของมันกับที่คุณเห็นเองใน Jira</do>
</b-finding>
</b-chapter>
<b-chapter id="saving" icon="coin-hm" title="การประหยัด">
<b-why align="left">การประหยัดมาจากความแม่นยำ คำขอที่คลุมเครือได้คำตอบที่คลุมเครือ การแก้ทำให้เกิดคำขอใหม่ และข้อผิดพลาดสะสมจากขั้นหนึ่งไปอีกขั้น เมื่อคัดลอกและเล่าซ้ำด้วยมือ คนเพิ่มความพลาดแบบนี้โดยไม่รู้ตัว เอเจนต์ดึงข้อมูลจากต้นทางโดยตรง สายโซ่จึงสั้นลงและมีข้อผิดพลาดน้อยลง ราคาที่ต้องจ่ายคือการใช้โทเคนที่เพิ่มขึ้นเมื่อทำงานยาว และมีตัวจำกัดสำหรับเรื่องนี้</b-why>
<b-lane title="ข้อผิดพลาดสะสม: ด้วยมือ หรือจากต้นทาง" color="accent">
<b-scene names="mcp-agent-access/exact-request"/>
</b-lane>
<b-why align="left">ด้านซ้ายคือเส้นทางที่คัดลอกด้วยมือ: ทุกขั้นเพิ่มความคลาดเคลื่อน และเมื่อถึงรอบที่สามข้อผิดพลาดก็สะสมแล้ว ด้านขวาคือเส้นทางจากต้นทาง: คำขอที่แม่นยำหนึ่งครั้งและคำตอบหนึ่งครั้ง ไม่มีสายโซ่ของการเล่าซ้ำ</b-why>
<b-spacer h="12"/>
<b-rules sw="1.8">
  <rule icon="eye" t="คำขอและคำตอบที่คลุมเครือ">การเล่าซ้ำและการคัดลอกด้วยมือทำให้รายละเอียดหาย คำขอจึงคลุมเครือ คำตอบก็เช่นกัน</rule>
  <rule icon="users" t="ข้อผิดพลาดสะสม">ทุกการแก้ก่อให้เกิดคำขอใหม่ที่มีความคลาดเคลื่อนใหม่: ข้อผิดพลาดบวกกันจากขั้นหนึ่งไปอีกขั้น</rule>
  <rule icon="layers" t="ต้นทุน: โทเคน">ขั้นตอนน้อยลง แต่การใช้โทเคนเพิ่มขึ้นเมื่อทำงานยาว มีขีดจำกัดสำหรับเรื่องนี้</rule>
</b-rules>
<b-section-h3 top="14">ขีดจำกัดการใช้จ่าย</b-section-h3>
<b-why align="left">คำตอบของระบบที่เชื่อมไว้ตกลงในบทสนทนาและกินที่ในนั้น ที่วัดเป็นโทเคน Claude Code จึงเฝ้าดูขนาดคำตอบและตั้งเกณฑ์สองระดับ</b-why>
<b-scene names="mcp-agent-access/reply-size-scale"/>
<b-why align="left">สเกลแสดงขนาดคำตอบของระบบเป็นโทเคน ไม่เกิน 10,000 โทเคน คำตอบผ่านโดยไม่มีข้อสังเกต เกิน 10,000 Claude Code เตือนว่าคำตอบใหญ่ เกิน 25,000 คำตอบจะไม่เข้าบทสนทนาทั้งก้อน และถูกบันทึกลงไฟล์</b-why>
<b-art-note top="6">เพดาน 25,000 ปรับเพิ่มได้ด้วยตัวแปรสภาพแวดล้อม MAX_MCP_OUTPUT_TOKENS ส่วนเกณฑ์เตือนตายตัว</b-art-note>
<b-why align="left"><a href="https://code.claude.com/docs/en/mcp" target="_blank" rel="noopener">อ่านเพิ่ม</a></b-why>
<b-finding>
  <ex>สามรอบที่ข้อผิดพลาดเพิ่มขึ้น กลายเป็นรอบเดียวกับคำขอที่แม่นยำ</ex>
  <gen>การประหยัดคือการไม่มีรอบเกิน: คำขอที่แม่นยำและคำตอบจากต้นทางไม่สะสมข้อผิดพลาด ตัวเลขที่แน่นอนได้จากการวัดงานของคุณเองเท่านั้น</gen>
  <gen k="เรื่องขีดจำกัด">ยิ่งงานยาว ยิ่งใช้โทเคนมาก Claude Code จึงจำกัดคำตอบยาว: เตือนหลัง 10,000 โทเคนและบันทึกลงไฟล์หลัง 25,000</gen>
  <do k="ควรทำ">วัดสองอย่างกับงานหนึ่งงาน: การถ่ายโอนด้วยมือใช้กี่นาทีและแก้กี่ครั้ง และเอเจนต์ใช้โทเคนเท่าไร</do>
</b-finding>
</b-chapter>
<b-chapter id="facts" icon="check-circle" title="hallucination น้อยลง">
<b-why align="left">Hallucination: โมเดลสร้างข้อความที่ดูถูกต้องแต่ผิด หรือไม่ได้มาจากข้อมูล โมเดลฟังดูมั่นใจเท่ากันในสองสถานการณ์ <a href="https://platform.claude.com/docs/en/test-and-evaluate/strengthen-guardrails/reduce-hallucinations" target="_blank" rel="noopener">อ่านเพิ่ม</a></b-why>
<b-rules-fixed cols="2" sw="1.8">
  <rule icon="help" t="บริบทน้อย">โมเดลเติมช่องว่างเองและไม่บอกว่าเป็นการเดา</rule>
  <rule icon="file-text" t="มีบริบท">โมเดลอ้างถึงอย่างฉะฉานและมั่นใจ จึงควรเปิดลิงก์และตรวจ</rule>
</b-rules-fixed>
<b-lane title="ที่ที่ข้อมูลขาด" color="accent" top="14">
<b-scene names="mcp-agent-access/fills-gaps"/>
</b-lane>
<b-art-note top="10" align="left">คำตอบของเอเจนต์ถูกจับคู่กับข้อมูล: ทุกส่วนควรมีหลักรองรับ ในทางคณิตศาสตร์การจับคู่แบบนี้เรียกว่า epimorphism ส่วนที่ไม่มีหลักรองรับ โมเดลเติมด้วยการเดา และดูมั่นใจเท่ากัน</b-art-note>
<b-why align="left">ในทางปฏิบัติหมายความว่า หากไม่ได้เชื่อมระบบ เอเจนต์เติมช่องว่างด้วยการเดาและพูดด้วยน้ำเสียงมั่นใจเท่าเดิม: ข้อความไม่แสดงว่าส่วนไหนเดาส่วนไหนข้อเท็จจริง หากเชื่อมระบบแล้ว ข้อมูลจริงพร้อมลิงก์จะอยู่ในที่ที่เคยเป็นการเดา และการตรวจใช้แค่คลิกเดียว คำแนะนำสามข้อของ Anthropic ทำงานร่วมกัน: อนุญาตให้เอเจนต์พูดว่า "ไม่รู้" เมื่อไม่มีข้อมูล ขอให้อ้างข้อความต้นฉบับตรง ๆ และเรียกร้องลิงก์สำหรับทุกข้ออ้าง</b-why>
<b-section-h3 top="18">สิ่งที่ Anthropic แนะนำ</b-section-h3>
<b-step-chain>
  <node t="&quot;ไม่รู้&quot;">อนุญาตให้ยอมรับว่าไม่มีข้อมูล</node>
  <node t="คำพูดที่ยก">อ้างข้อความต้นฉบับตรง ๆ</node>
  <node t="การอ้างอิง">ทุกข้ออ้างมีแหล่งที่มา</node>
</b-step-chain>
<b-why align="left">คำแนะนำสามข้อของ Anthropic ปิดช่องว่างในข้อมูล อนุญาตให้พูดว่า "ไม่รู้": มิฉะนั้นโมเดลเติมช่องด้วยการเดา อ้างคำพูด: ข้อความต้นฉบับตรวจได้ ให้ลิงก์ทุกข้ออ้าง: เปิดและเทียบได้</b-why>
<b-finding>
  <ex>Jira ปิดอยู่ เอเจนต์จึงแต่งสองส่วนของคำตอบ เมื่อเชื่อม Jira ที่ตรงนั้นเป็นข้อมูลจากตั๋ว PAY-142 พร้อมลิงก์ และคุณเปิดได้ในคลิกเดียว</ex>
  <gen>เอเจนต์เติมช่องโหว่ในข้อมูลด้วยการเดาและไม่บอก คำแนะนำสามข้อของ Anthropic ปิดช่องเหล่านั้น: อนุญาต "ไม่รู้" อ้างคำพูด ให้ลิงก์แหล่งที่มา วิธีนี้ไม่ได้ขจัด hallucination ทั้งหมด การตรวจโดยคนยังคงอยู่</gen>
  <do k="ควรทำ">เรียกร้องแหล่งที่มาสำหรับทุกข้อเท็จจริง: ระบบ หมายเลข ฟิลด์ วิธีทำในข้อกำหนดและบันทึกการประชุมอยู่ใน<a href="/blog/requirements-sources-facts-assumptions/">บทความแยก</a></do>
</b-finding>
</b-chapter>
<b-chapter id="risks" icon="shield-check" title="ความเสี่ยงและกฎ">
<b-why align="left">ในกรณีส่วนใหญ่ การป้องกันถูกสร้างไว้ในวิธีที่ MCP ทำงานใน Claude Code อยู่แล้ว สิ่งที่เหลือคือเลือกเซิร์ฟเวอร์ที่ไว้ใจได้และไม่ให้สิทธิ์เกินจำเป็น <a href="https://code.claude.com/docs/en/mcp" target="_blank" rel="noopener">อ่านเพิ่ม</a></b-why>
<b-why align="left">ความเสี่ยงสามข้อที่ควรจำ สิทธิ์เกิน: เซิร์ฟเวอร์ที่ได้สิทธิ์เขียนแก้ไขหรือลบข้อมูลได้ จึงให้สิทธิ์เท่าที่จำเป็น เซิร์ฟเวอร์ที่ไม่ไว้ใจ: เซิร์ฟเวอร์ MCP ของบุคคลที่สามเข้าถึงสิ่งที่คุณเปิดให้ จึงเชื่อมเฉพาะที่ผ่านการตรวจสอบ ข้อความจากระบบ: งานหรือความเห็นอาจมีประโยคที่มุ่งเล่นงานเอเจนต์ ซึ่งอธิบายในบทความ [เรื่อง data plane และ control plane](/blog/data-plane-control-plane-prompt-injection/)</b-why>
<b-rules sw="1.8">
  <rule icon="bell" t="การขออนุญาต">Claude Code ขออนุญาตก่อนใช้เครื่องมือของเซิร์ฟเวอร์</rule>
  <rule icon="folder-hm" t="เซิร์ฟเวอร์ของโปรเจกต์">เซิร์ฟเวอร์จากไฟล์ .mcp.json ของโปรเจกต์ต้องได้รับการอนุมัติก่อนใช้ครั้งแรก</rule>
  <rule icon="key" t="สิทธิ์">สำหรับเซิร์ฟเวอร์ที่มีการล็อกอิน จำกัดได้ว่าขอสิทธิ์อะไร</rule>
</b-rules>
<b-lane title="บันไดสิทธิ์" color="accent" top="14">
<b-scene names="mcp-agent-access/rights-ladder"/>
</b-lane>
<b-why align="left">บันไดในภาพแสดงลำดับการให้สิทธิ์ ก่อนอื่นอ่าน: เอเจนต์ดูอย่างเดียว จากนั้นเขียนพร้อมการยืนยัน: เอเจนต์เสนอ คนอนุมัติทุกการเขียน เขียนโดยไม่ต้องยืนยันรอจนกว่าจะสร้างความไว้ใจได้ ขึ้นไปทีละขั้นเมื่อตรวจแล้วว่าขั้นก่อนหน้าใช้ได้</b-why>
<b-finding>
  <ex>เอเจนต์อ่าน prod เขียนเฉพาะชีตทดสอบ และแสดงทุกการเขียนให้คนเห็น</ex>
  <gen>สิทธิ์เพิ่มขึ้นตามบันได: อ่านก่อน แล้วเขียนที่ได้รับการยืนยัน การเขียนที่ไม่ต้องยืนยันรอจนกว่าจะได้รับความไว้ใจ</gen>
  <do k="ควรทำ">ให้เซิร์ฟเวอร์ใหม่อ่านอย่างเดียว แล้วเพิ่มสิทธิ์หลังจากทำงานที่ตรวจแล้วมาหนึ่งสัปดาห์</do>
</b-finding>
</b-chapter>
<b-chapter id="first" icon="arrow-right" title="เริ่มจากตรงไหน">
<b-why align="left">ควรเริ่มเล็ก ๆ: หนึ่งแหล่ง หนึ่งคนที่ตรวจ และโหมดอ่านอย่างเดียว เชื่อม Jira ถามเอเจนต์ห้าคำถามเกี่ยวกับงานจริง แล้วเทียบคำตอบกับที่คุณเห็นเอง วิธีนี้แสดงว่าไว้ใจเอเจนต์ได้แค่ไหนก่อนจะให้สิทธิ์เขียน</b-why>
<b-scene names="mcp-agent-access/start-small"/>
<b-finding>
  <ex>เริ่มจาก Jira แบบอ่านอย่างเดียว และเทียบคำตอบของเอเจนต์ห้าข้อกับที่คุณเห็นเอง</ex>
  <gen>หนึ่งแหล่ง หนึ่งผู้ตรวจ ทีละขั้นของสิทธิ์</gen>
  <do k="ควรทำ">เชื่อมเซิร์ฟเวอร์แรกวันนี้ และจดว่าเอเจนต์อ่านอะไรถูกและอะไรผิด</do>
</b-finding>
</b-chapter>
