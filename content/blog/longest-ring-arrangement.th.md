การเรียงที่คลายยากที่สุดน่าจะเป็น "กระจก" คือวงแหวนที่สะท้อนผ่านช่องสลับ และต้องใช้ท่าเท่ากับจำนวนคู่ของลูกบอล: n(n−1)/2 การไล่ทุกกรณีถึง 15 ลูก โครงข่ายประสาทเทียมกับ beam search ถึง 100 ลูก และการแข่งขันแบบเปิดถึง 200 ลูก ให้ผลตรงกันทั้งหมด ส่วนการพิสูจน์บีบคำตอบให้อยู่ในช่วงแคบๆ

<b-chapter id="question" icon="grid" title="โจทย์: วงแหวน สามท่า และการเรียงที่พันที่สุด">
  <b-why>สมมติมีวงแหวนลูกบอลที่แต่ละลูกมีหมายเลข สลับอย่างไรก็เรียงกลับเป็นลำดับได้เสมอ คำถามคือการเรียงแบบไหนคลายยากที่สุด และต้องใช้กี่ท่า</b-why>

  มีสามคำที่ต้องรู้ **ท่า** คือหมุนวงแหวนไปทางซ้าย หมุนไปทางขวา หรือสลับลูกบอลสองลูกใน**ช่อง**ด้านบน **การเรียง** คือลำดับของลูกบอลรอบวง ไม่มีท่าอื่น: หยิบลูกบอลจากกลางวงไม่ได้ ทุกอย่างต้องผ่านช่อง

  <b-art names="longest-ring-arrangement/moves"/>
  <b-cap>ซ้าย: ลูกบอลเรียงตามลำดับ กลาง: หลังหมุนซ้าย ขวา: หลังสลับในช่อง <a href="https://youtu.be/ecc2GvvZGvM?t=8" target="_blank" rel="noopener">▶ 0:08</a></b-cap>

  ทำไมจึงยาก? คลายการเรียงใดๆ ก็ได้ไม่ยาก: นำลูกที่ต้องการมาที่ช่องแล้วสลับไปเรื่อยๆ จนทุกอย่างเข้าที่ แต่วิธีนั้นเปลืองท่ามาก การรู้จำนวนท่าที่น้อยที่สุดต้องเทียบทุกเส้นทาง และวงแหวนมีการเรียง 1·2·3·…·n แบบ ซึ่งโตเร็วกว่าเลขยกกำลังใดๆ

  โจทย์ที่เกี่ยวข้อง — วงแหวนเดิมที่หมุนทางเดียวกับการสลับ — ถูกตั้งโดยนักไซเบอร์เนติกส์ Viktor Glushkov ในปี 1968 และยังไม่มีคำตอบ
</b-chapter>

<b-chapter id="paper" icon="trophy" title="บทความ ผู้เขียน และการแข่งขัน">
  <b-why>โจทย์นี้ศึกษาโดยผู้เขียน 34 คนของโครงการ CayleyPy — ทีมเดียวกับที่สอนโครงข่ายประสาทเทียมให้<a href="/blog/rubik-cube-neural-network/">แก้ลูกบาศก์รูบิก 4×4×4 และ 5×5×5</a></b-why>

  "CayleyPy RL" เป็นบทความชิ้นที่สองของชุดนี้: ชิ้นแรกแสดงวิธีกับลูกบาศก์ ชิ้นนี้ขยายไปสู่กราฟเคย์ลีย์ทั่วไปและทดสอบกับวงแหวนลูกบอล ในบทความนี้มีสี่วิธีตอบคำถามเดียวมาพบกัน: ไล่ทุกกรณีกับวงแหวนเล็ก โปรแกรมที่ฝึกแล้วสำหรับวงใหญ่ การแข่งขันเขียนโปรแกรมแบบเปิด และการพิสูจน์อย่างเข้มงวด

  <b-art names="longest-ring-arrangement/authors"/>
  <b-cap>ผู้เขียน 34 คนตามลำดับในบทความ ชื่อตามที่พิมพ์ในบทความ</b-cap>

  Kaggle เป็นแพลตฟอร์มที่นักวิจัยโพสต์โจทย์ และทีมจากทั่วโลกแข่งกันหาคำตอบ ผู้เขียนเปิดการแข่งขันสามรายการเกี่ยวกับวงแหวนนี้ที่นั่น และเผยแพร่โค้ดให้ใครก็รันและพยายามทำให้ดีกว่าได้
</b-chapter>

<b-chapter id="tower" icon="boxes-route" title="ตึกของการเรียง: ชั้นและเพดาน">
  <b-why>ลองวาดการเรียงทั้งหมดพร้อมกัน ลูกบอลห้าลูกมี 120 แบบ</b-why>

  วางแต่ละการเรียงไว้บน**ชั้น**: ห่างจากลำดับเรียบร้อยกี่ท่าตามเส้นทางสั้นที่สุด ลำดับเรียบร้อยอยู่ล่างสุด ชั้นแรกมีสามเพื่อนบ้าน (หนึ่งต่อหนึ่งท่า) จากนั้นชั้นกว้างขึ้นแล้วแคบลงอีกครั้ง ชั้นบนสุดคือ**เพดาน**: จำนวนท่านั้นพอสำหรับทุกการเรียง ลูกบอลห้าลูกมีเพดานที่ชั้น 10 และมีการเรียงเดียวเท่านั้นที่อยู่ตรงนั้น

  <b-art names="longest-ring-arrangement/tower"/>
  <b-cap>ความกว้างของแท่งคือจำนวนการเรียงบนชั้นนั้น คำนวณด้วยการไล่ทุกกรณี <a href="https://youtu.be/ecc2GvvZGvM?t=73" target="_blank" rel="noopener">▶ 1:13</a></b-cap>

  เพดานคือสิ่งเดียวกับ<a href="/blog/rubik-cube-neural-network/">God's number ของลูกบาศก์รูบิก</a>: จำนวนท่ามากที่สุดที่คำตอบสั้นที่สุดอาจต้องใช้ ในทางคณิตศาสตร์คือเส้นผ่านศูนย์กลางของกราฟ ถ้ารู้ชั้นของทุกการเรียง การคลายก็ง่าย: ก้าวลงหนึ่งชั้นทุกครั้ง
  <b-steps top="14" round>
    <step t="ชั้น">ห่างจากลำดับเรียบร้อยกี่ท่าตามเส้นทางสั้นที่สุด</step>
    <step t="เพดาน">ชั้นบนสุด: จำนวนท่าที่พอสำหรับทุกการเรียง คือ God's number และเส้นผ่านศูนย์กลางของกราฟ</step>
    <step t="โจทย์">ใครอยู่บนเพดาน และเพดานสูงเท่าไรเมื่อลูกบอลมีกี่ลูกก็ได้</step>
  </b-steps>
</b-chapter>

<b-chapter id="mirror" icon="search" title="ใครอยู่บนเพดาน: กระจก">
  <b-why>ผู้เขียนไล่ทุกการเรียงของวงแหวนถึง 15 ลูก สำหรับ 15 ลูกมีมากกว่าหนึ่งล้านล้านแบบ และใช้คลัสเตอร์หลายวัน</b-why>

  ทุกครั้งมีการเรียงเดียวอยู่บนสุด คือ **กระจก**: วงแหวนที่สะท้อนผ่านช่อง ลูกบอลสองลูกในช่องสลับกัน ส่วนที่เหลือสลับเป็นคู่ข้ามแกน น่าแปลกที่แค่เรียงลูกบอลย้อนกลับกลับอยู่ต่ำกว่าสองชั้น

<b-chapter id="gap" icon="flag-alt" title="ยี่สิบลูก: การไล่ทุกกรณีเอื้อมไม่ถึง">
  <b-why>ลูกบอลยี่สิบลูกมีการเรียงถึง 2.4·10¹⁸ แบบ — หลายพันล้านพันล้าน ข้อคาดการณ์จึงทดสอบด้วยวิธีอื่น: เอากระจกมาหาทางคลายที่สั้นกว่า</b-why>

  ถ้าเส้นทางไม่เคยสั้นกว่าจำนวนคู่ ข้อคาดการณ์ก็ยังถูก เริ่มจากโปรแกรมพีชคณิตเชิงคอมพิวเตอร์แบบคลาสสิกสำหรับกลุ่ม (GAP) มันหาเส้นทางได้เสมอแต่ไม่สนใจความยาว: กับวงแหวน 20 ลูก ทำงาน 41 นาทีและให้ผล 217,944 ท่า ทั้งที่มีแค่ 190 คู่

<b-chapter id="compass" icon="search" title="เข็มทิศจากวิดีโอก่อนหน้า">
  <b-why>ผู้เขียนใช้เทคนิคเดิมจาก<a href="/blog/rubik-cube-neural-network/">ลูกบาศก์รูบิก</a>: เข็มทิศที่ฝึกจากการเดินสุ่ม</b-why>

  ก่อนอื่นคือ **การเดินสุ่ม**: เริ่มจากลำดับเรียบร้อย ทำท่าแบบสุ่ม และหลังแต่ละท่าบันทึกการเรียงกับจำนวนท่าที่ทำไป ไม่ต้องมีแผนที่ของทุกการเรียง และการเดินสุ่มแทบไม่มีต้นทุน **เข็มทิศ** เรียนรู้จากบันทึกเหล่านี้ — เป็นโครงข่ายประสาทเทียมที่ดูการเรียงหนึ่งแล้วเดาชั้นของมัน

  <b-art names="longest-ring-arrangement/net"/>
  <b-cap>เข็มทิศเป็นโครงข่ายประสาทเทียมธรรมดา: ใส่การเรียงเข้า ได้ตัวเลขออก</b-cap>

  เข็มทิศเดาผิดได้: การเดินสุ่มวนเป็นลูป จึงมีท่ามากกว่าเส้นทางที่สั้นที่สุด แต่ยิ่งเดินไกล ชั้นเฉลี่ยก็ยิ่งสูง เข็มทิศจึงชี้ถูกทาง: ตรงที่ตัวเลขน้อยกว่า ลำดับเรียบร้อยอยู่ใกล้กว่า

  ความใหม่ของบทความอยู่ที่วิธีฝึกเข็มทิศ การเดินสุ่มให้ค่าเดาแรก จากนั้นเข็มทิศถูกตรวจกับเพื่อนบ้าน: ไปถึงลำดับเรียบร้อยมากกว่าเพื่อนบ้านที่ใกล้ที่สุดหนึ่งท่า เหมือนทางกลับบ้าน: ถ้าเพื่อนบ้านอยู่ห่างห้านาที คุณก็ห่างไม่เกินหกนาที กับวงแหวน 28 ลูก วิธีนี้ลดเส้นทางทั่วไปจาก 650 ท่าเหลือ 402 ท่า โดยมี 378 คู่

  <b-codebox copy>
    def beam_search(start, model, W, steps=1000):
        front = [start]
        for _ in range(steps):
            nbrs = {m(s) for s in front for m in (L, R, X)
                    if not (m is X and s[0] < s[1])}   # the hint
            if SORTED in nbrs: return True
            front = sorted(nbrs, key=model)[:W]   # W best by the compass
        return False
  </b-codebox>

    <q t="เส้นผ่านศูนย์กลางของวงแหวนที่หมุนและสลับได้เท่ากับเท่าไร">ตามข้อคาดการณ์คือ n(n−1)/2 — จำนวนคู่ของลูกบอล ตั้งแต่สี่ลูกขึ้นไป การไล่ทุกกรณียืนยันถึง 15 ลูก และพิสูจน์แล้วว่าอยู่ระหว่าง n(n−1)/2 − n/2 − 1 กับ n(n−1)/2 + 3n</q>
    <q t="ข้อคาดการณ์พิสูจน์แล้วหรือยัง">ยังไม่สมบูรณ์ ในปี 2026 หนึ่งในผู้เขียนโพสต์การพิสูจน์ขอบล่างที่เท่ากับจำนวนคู่พอดี แต่เป็นพรีปรินต์ ส่วนขอบบนยังสูงกว่าอยู่ 3 ท่าต่อลูกบอลหนึ่งลูก</q>
    <q t="โครงข่ายประสาทเทียมหาเส้นทางในกราฟมหึมาได้อย่างไร">โครงข่ายเข็มทิศเรียนรู้จากการเดินสุ่มให้เดาระยะถึงเป้าหมาย และ beam search เก็บสถานะที่ดีที่สุดจำนวนมากตามค่าประมาณของมันพร้อมกัน ความผิดพลาดครั้งเดียวจึงไม่พาไปสู่ทางตัน</q>
    <q t="ลองเองได้ไหม">ได้ โค้ดของผู้เขียนเปิดเผยและรันฟรีบน Kaggle และไลบรารี CayleyPy อยู่บน GitHub (ลิงก์ด้านล่าง)</q>
