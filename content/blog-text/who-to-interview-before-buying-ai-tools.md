## Какое решение поможет принять

Отчёт об использовании показывает, кто и сколько работает с инструментом. Причины и задачи за этими цифрами можно узнать только в разговоре. Короткий список людей решает, какие гипотезы про новые инструменты вообще будут проверены.

Вход

Таблица людей из отчёта: траты по продуктам, сообщения, проекты, команда

Что делает метод

Отбирает по 2–3 человека на каждый крайний сценарий использования

Решение на выходе

С кем говорить перед покупкой и какие гипотезы про инструменты проверять

## Почему одного топа по активности мало

Три способа набрать 16 человек. Цвет точки — сценарий использования. Самые активные и добровольцы — хорошие респонденты, их берут в любую выборку, но одних их мало.

**Вывод:**

**В этом примере:** Топ по сообщениям покрывает 2 сценария из 7, добровольцы — 3, полярные группы — все 7.

**В общем случае:** Самые активные и отзывчивые люди лучше всех знают инструмент, и их стоит звать. Они похожи друг на друга и вместе описывают один-два сценария. Чтобы услышать остальные, выборку добирают людьми с крайними значениями других признаков.

**Что сделать:** Возьмите 2–3 человек из топа по сообщениям. Остальные места отдайте людям с другими сценариями: тем, кто платит без чата, не пользуется совсем или ведёт много проектов.

## Группа, которую обычно забывают

Проверка после первых шести групп: сколько отобранных людей пришлось на каждую команду.

|---|---|---|---|
| Команда A |  |  | покрыта |
| Команда B |  |  | покрыта |
| Команда C |  |  | покрыта |
| Команда D |  | 0 | + 1 человек |
| Команда E |  | 0 | + 2 человека |

**Вывод:**

**В этом примере:** В командах D и E после шести групп не оказалось ни одного человека.

**В общем случае:** Пороги по тратам и сообщениям ловят крайних пользователей. Команда, где все пользуются понемногу, под пороги не попадает, и её задачи выпадают из исследования. Поэтому команды проверяют отдельно.

**Что сделать:** Когда люди отобраны по порогам трат и сообщений, разложите их по командам. В каждую команду, где никого нет, добавьте 1–2 человек с самой высокой активностью внутри неё.

## Что узнать на интервью

Шесть пунктов по ходу одной реальной задачи — от момента, когда она появилась, до её влияния на работу.

Ситуация

- **Последняя задача:** Когда, зачем, для кого
- **Прежний способ:** Как делали без AI-инструмента

Ожидание

- **На что рассчитывали:** Какой результат и за какое время

Результат

- **Что вышло:** Что взяли в работу как есть
- **Точка отказа:** Где бросили или переписали сами

Эффект

- **Что поменялось в работе:** Сроки, объём, роли в команде

**Вывод:**

**В этом примере:** Шесть пунктов идут по ходу одной задачи: от ситуации до эффекта на работу.

**В общем случае:** Разница между ожиданием и результатом показывает, где текущий инструмент не дотягивает, а точка отказа — какую возможность искать в новом. Рассказ о прошлом даёт факты, прогноз о будущем проверить нельзя.

**Что сделать:** Перед интервью найдите в отчёте последнюю активность человека или попросите в первые две минуты назвать последнюю задачу и ведите весь разговор по ней.

## Порядок работы

1

Отфильтровать таблицу людей по шести порогам поведения

По 2–5 кандидатов на группу, отсортированных по сумме или числу сообщений

2

Оставить по 2–3 человека в группе

Из разных команд, если есть выбор

3

Проверить покрытие команд

Добавить людей из команд, где никого не отобрали, — это седьмая группа

4

Назначить интервью по 40 минут

Разговор идёт по шести пунктам: последняя задача, прежний способ, ожидание, результат, точка отказа, эффект. С неактивными вместо задачи обсуждают, что помешало начать

**Ограничение.** 16 интервью показывают, какие проблемы встречаются и как они выглядят в работе. Сколько людей в компании сталкивается с каждой из них, по 16 разговорам не посчитать. Чтобы узнать масштаб, отправьте всей компании короткий опрос из 2–3 вопросов про найденные проблемы.
