reconcile loop მიჰყვება Kubernetes-ის დოკუმენტაციას კონტროლერების შესახებ.

**დასკვნა:**

**ამ მაგალითში:** Kubernetes-ში ადამიანი chart-ს ცვლის, კონტროლერი კი nodes-ს მასთან აახლოებს. აქ ადამიანი ლექსიკონს ცვლის, აგენტი კოდს მასთან აახლოებს და ტესტებით ამოწმებს.

**ზოგადად:** ორივე სისტემა სასურველ მდგომარეობას რეალურისგან ცალკე ინახავს და ციკლით ათანხმებს. ციკლში მყოფი ადამიანი მხოლოდ სასურველ მდგომარეობას ცვლის, ამიტომ ყოველი ცვლილება მაშინვე შემსრულებლის სამუშაოდ იქცევა.

**შემდეგი ნაბიჯი:** მოთხოვნა ლექსიკონში შეასწორეთ და ნუ შეასწორებთ კოდს ხელით; აგენტს კი დაავალეთ, კოდი ლექსიკონთან მიიყვანოს.

## შემოწმება მხოლოდ იმას ხედავს, რაც მასში ჩაიდო

მაგალითად აღებულია სათათბირო ოთახის ჯავშანი სტატიიდან სპეციფიკაციები აგრეგატების მიხედვით: სამი MUST მოთხოვნა და ერთი SHOULD.

**2 / 3:**

ტესტები მწვანეა, ერთი MUST შეუმოწმებელია

ყოველ MUST-ს → საკუთარი შემოწმება MUST შემოწმების გარეშე = ხარვეზი მწვანე ≠ სწორი

რა probe-ები არსებობს და რას ამოწმებს: Kubernetes: probes.

**დასკვნა:**

**ამ მაგალითში:** probe „200“-ს აბრუნებს, შეკვეთები კი გაჭედილია; ჯავშნის ტესტები მწვანეა, 15-წუთიან წესს კი ვერავინ ამოწმებს.

**ზოგადად:** შემოწმება მხოლოდ იმას ადასტურებს, რაც მასშია ჩაწერილი, დანარჩენზე კი არაფერს ამბობს. ამიტომ აგრეგატის ბარათს შემოწმებებთან ადარებენ: MUST შემოწმების გარეშე ხარვეზია და არა შესრულებული მოთხოვნა.

**შემდეგი ნაბიჯი:** გადაიარეთ თქვენი ლექსიკონის MUST-ები და მონიშნეთ ისინი, რომლებსაც ტესტი არ აქვს. თითოეული გადააქციეთ ამოცანად ან შეგნებულად დააქვეითეთ SHOULD-მდე.

## გარემო წყვეტს, დაიხურება თუ არა ციკლი

**კლასტერი:** კონტროლერის გარემო

≈

**harness:** აგენტის გარემო

**კოდის გაშვება:** მის გარეშე → ფაქტების ნაცვლად ვარაუდი

**ტესტები:** მათ გარეშე → MUST-ის შემოწმება შეუძლებელია

**ლოგები:** მათ გარეშე → არ ჩანს, რა გაფუჭდა

**სატესტო მონაცემები:** მათ გარეშე → შემოწმება ცარიელ ცხრილებზე

**სერვისები MCP-ით:** მათ გარეშე → ინტეგრაციები ბნელში

**სენდბოქსი და უფლებები:** მათ გარეშე → აგენტისთვის მოქმედების დაშვება სარისკოა

ცალკე სტატია გარემოს არჩევა: harness-ების შედარება Claude Code, Codex, Cursor, Hermes და ჩატი ერთ რუკაზე

**დასკვნა:**

**ამ მაგალითში:** Kubernetes-ის კონტროლერი იმიტომ მუშაობს, რომ კლასტერი მას აძლევს API-ს, nodes-ს და probes-ს. იმავე ციკლისთვის აგენტს სჭირდება კოდის გაშვება, ტესტები, ლოგები, მონაცემები, სერვისები და სენდბოქსი.

**ზოგადად:** ლექსიკონი სასურველ მდგომარეობას ადგენს, მაგრამ მასთან შეთანხმება მხოლოდ იმას შეუძლია, ვისაც კოდის გაშვება და გაზომვა შეუძლია. რაც გარემოს აკლია, იმას აგენტი ვერ შეამოწმებს და ციკლი სწორედ ამ ადგილას რჩება ღია.

**შემდეგი ნაბიჯი:** მონიშნეთ, ექვსი შესაძლებლობიდან რომელი აქვს თქვენს აგენტს. თითოეული მიუწვდომელისთვის გადაწყვიტეთ: დაამატოთ harness-ს თუ harness შეცვალოთ.
