# Переводы на новые языки

Языки: тайский `th`, грузинский `ka`, вьетнамский `vi`, испанский `es`, французский `fr`.
Адреса: `/th/…`, `/ka/…`, `/vi/…`, `/es/…`, `/fr/…`. Английский — в корне, русский — `/ru/…`.

Исходные тексты не трогаем: пары `{ ru, en }` в `src/data/*.ts` и посты `content/blog/*.md`, `*.en.md`.
Переводим с английского. Каждый переводчик пишет только в свои файлы — конфликтов нет.

## Правило: страница есть, только если переведена

- **Единица перевода** (термин, оффер, игра, рубрика…) готова на языке, когда у каждой её пары `{ ru, en }`
  есть перевод. Пары, где `ru` и `en` совпадают (имена продуктов, код, `yes`/`no` в таблицах), переводить не нужно.
  Необязательные поля готовность не держат: `match` у терминов, `href` у пунктов меню.
- **Страница** на новом языке собирается, попадает в sitemap, hreflang и переключатель языков, только если готово
  всё, из чего она собрана (таблица ниже). Иначе адреса нет: сборка его не создаёт, а SPA отвечает 404.
- Ссылка со страницы на новом языке ведёт на перевод, если он есть, иначе на английскую страницу.
- Строки интерфейса (`ui.json`) готовность не держат: без перевода строка остаётся английской.
  Поэтому `ui.json` переводится первым.

| Страница | Нужно для появления |
|---|---|
| `/<язык>/materials/glossary/<slug>` | термин `<slug>` в `glossary.json` + его набор в `glossarySets.json` |
| `/<язык>/materials/glossary` | `seo.json` → `/materials/glossary`, весь `glossarySets.json`, хотя бы один термин (в списке — только переведённые) |
| `/<язык>/blog/<slug>` | файл `content/blog/<slug>.<язык>.md` |
| `/<язык>/blog`, рубрики, страницы ленты | `seo.json` → `/blog`, весь `blog.json`, хотя бы один пост |
| `/<язык>/ai/<slug>` | оффер в `aiOffers.json` + весь `ai.json` |
| `/<язык>/ai` | `seo.json` → `/ai`, весь `ai.json`, хотя бы один оффер |
| `/<язык>/materials/games/<slug>` | игра в `games.json` |
| `/<язык>/materials/interactive/<slug>` | интерактив в `labs.json` |
| `/<язык>/` | `seo.json` → `/`, весь `nav.json` и `profile.json` |
| `/<язык>/about` | `seo.json` → `/about`, весь `about.json`, `places.json`, `links.json` |
| `/<язык>/links` | `seo.json` → `/links`, весь `links.json` |
| `/<язык>/materials` · `/materials/presentations` | только `seo.json` |
| `/<язык>/materials/games` · `/materials/interactive` | `seo.json` + весь `games.json` / `labs.json` |
| доклад `/talk/…`, слайды, паттерны, архитектура игр, витрина блоков | только ru/en, не переводятся |

## Файлы

```
src/i18n/<язык>/
  ui.json            строки интерфейса: { "<английский текст>": "перевод" }
  seo.json           заголовки разделов: { "/about": { "title": "…", "description": "…" } }
  nav.json           меню                    id = to пункта: "/about", "https://jaiora.me/"
  glossary.json      термины                 id = slug термина
  glossarySets.json  наборы терминов         id = slug набора
  aiOffers.json      офферы /ai/<slug>       id = slug оффера
  ai.json            группы и факты хаба /ai id = "group:<id>", "proof:<value>"
  games.json         страницы игр            id = slug игры
  labs.json          страницы интерактивов   id = slug
  blog.json          рубрики блога           id = slug рубрики
  about.json         «Обо мне»               id = "lead", "milestones"
  profile.json       факты на главной        id = "profile"
  places.json        города на карте         id = "places"
  links.json         ссылки                  { "<url записи>": { "label": "…", "comment": "…" } }
  <модуль>.<часть>.json  та же схема: части одного модуля сливаются по id (для деления между переводчиками)
content/blog/<slug>.<язык>.md          перевод поста
content/blog-text/<slug>.<язык>.md     текстовая копия широкого поста (если есть у .en.md)
```

### Ключи модулей

Внутри единицы ключ — путь к паре через точку, номера элементов списка — числа:

```json
{
  "openspec": {
    "def": "…",
    "faq.0.q": "…",
    "faq.0.a": "…",
    "seo.title": "…",
    "source.label": "…"
  }
}
```

Значение — того же вида, что у английского: строка → строка, список → список той же длины
(например, `pains`, `outcomes`, `intro`, строки таблиц `table.rows.0`, пары `faq` у игр).
Готовые ключи и английский текст: `npm run i18n:status -- <язык> <модуль>` выводит недостающие ключи,
текст смотреть в `src/data/<модуль>.ts` (для игр — `src/data/games.generated.json`).

### `ui.json`

Ключ — английский текст строки ровно как в коде (`t({ ru: '…', en: 'Glossary' })` → `"Glossary"`).
Сменится английский — перевод перестанет находиться (`i18n:status <язык> ui` покажет такие ключи).
Шаблоны: `{name}`, `{n}`, `{total}` оставлять как есть — `"{name}: what it is — AI development glossary"`,
`", page {n}"`, `" Page {n} of {total}."`. Строки, собранные из `${…}` в коде, не переводятся.

## Что переводить и что оставлять

- Переводить: названия, определения, вопросы-ответы, подписи, описания, `seo.title` / `seo.description`
  (до ~160 знаков), подписи `label` у ссылок.
- Оставлять как есть: slug, id, url, пути и команды в обратных кавычках (`` `openspec/specs` ``, `/opsx:apply`),
  формулы `$…$`, названия продуктов и компаний (OpenSpec, Claude Code, GitHub), `yes` / `no` / `part` в матрицах,
  разметку Markdown и HTML, пустую строку между абзацами в `screens`.
- `match` у терминов — регулярные выражения для поиска термина в постах на этом языке. Необязательно:
  без него ищутся английские шаблоны.
- Тайский: термины ищутся в тексте по границам слов, а в тайском нет пробелов — автоссылки на термины в тайских
  постах будут редкими. Определение термина лучше заканчивать точкой: первая фраза до точки идёт в подсказки и карточки.

## Перевод поста

1. Скопировать `content/blog/<slug>.en.md` в `content/blog/<slug>.<язык>.md`, перевести текст.
2. Шапка — того же вида: `title`, `description`, `date`, `updated`, `category`, `tags`, `toc`, `mentions`, `layout`, `image`, `math`.
   - `date` — как у оригинала. `updated` — день перевода (сегодня). Сборка падает, если текст файла правили позже его `updated`
     (проверка идёт по каждому файлу языка отдельно); правка одной строки `updated:` правкой не считается.
   - `category`, `image`, `math`, `layout`, `mentions` — без изменений. `tags`, `title`, `description` — перевести.
   - `toc`: `id=Подпись | id=Подпись` — `id` не трогать (на них ссылки `#id` в тексте), подписи перевести.
3. Первый абзац — прямой ответ на вопрос заголовка (40–60 слов), как в оригинале.
4. Метки блоков `<b-…>`, `<iso-art name="…">` и их атрибуты не менять, переводить только текст внутри.
   Схемы `<iso-art>` пока рисуются по-английски.
5. Внутренние ссылки `/blog/<slug>/`, `/materials/glossary/<slug>/` писать без языка — язык подставится сам.
6. Если есть `content/blog-text/<slug>.en.md` — сделать и `content/blog-text/<slug>.<язык>.md`.

## Проверка

```
npm run i18n:status                       # сводка по всем языкам
npm run i18n:status -- es                 # один язык
npm run i18n:status -- es glossary        # недостающие ключи модуля
npm run i18n:status -- es glossary codex  # одной единицы
npm run i18n:status -- es ui              # непереведённые строки интерфейса (и устаревшие ключи)
npm run i18n:status -- es seo             # разделы без title/description
npm run i18n:status -- es posts           # посты без перевода
GAMES_DIR=…/awesome-games npm run build   # сборка; ошибки файлов переводов печатаются в начале prerender
```

Ошибки файлов (неизвестный id или путь, значение не того вида) не роняют сборку, но такой ключ не применяется,
а `i18n:status` завершается с кодом 1.

## Объём на один язык и деление на 4 переводчиков

| Модуль | Единиц | Ключей |
|---|---|---|
| `ui.json` | — | ≈150 строк |
| `seo.json` | 10 разделов | 20 |
| `nav` | 7 | 12 |
| `profile`, `about`, `places` | 1 + 2 + 1 | 4 + 21 + 27 |
| `links` | ≈60 записей | 70 |
| `blog` (рубрики) | 4 | 8 |
| `ai` + `aiOffers` | 7 + 8 | 10 + 64 |
| `games` | 8 | 112 |
| `labs` | 1 | 6 |
| `glossarySets` | 14 | 28 |
| `glossary` | 163 термина | 1572 (≈25 тыс. слов) |
| посты | 34 с английской версией | ≈85 тыс. слов с разметкой |

Термины по наборам (терминов / ключей): agents 10/174, coding-agents 9/167, companies 10/61, harness 15/126, mcp 8/75,
systems 5/30, specs 38/306, languages 8/55, testing 10/85, environments 9/124, delivery 6/56, formal 16/131,
models 5/52, group-theory 14/130.

Деление на четверых в одном языке (каждый пишет только в свои файлы и свои id):

1. **Сайт:** `ui`, `seo`, `nav`, `profile`, `about`, `places`, `links`, `blog`, `ai`, `aiOffers`, `games`, `labs`, `glossarySets`.
2. **Глоссарий, часть 1:** наборы agents, coding-agents, companies, harness, mcp, systems, models, languages, delivery (≈800 ключей).
3. **Глоссарий, часть 2:** наборы specs, testing, environments, formal, group-theory (≈780 ключей).
4. **Посты:** по размеру, крупные первыми (`npm run i18n:status -- <язык> posts`); при нехватке времени — делить посты с 2 и 3.

Модуль можно делить на файлы: `glossary.json`, `glossary.a.json`, `glossary.b.json` — сборка сливает их по id.
Поэтому переводчики 2 и 3 пишут каждый в свой файл (`glossary.a.json` и `glossary.b.json`) и не мешают друг другу.
Порядок id в файле не важен. `ui.json` — всегда один файл.
